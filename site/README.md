# EPL 2026-27 Dashboard

Static site (Vite + React + TypeScript + Tailwind v4 + Recharts) that
reads `../data/outputs/dashboard/*.json` -- the real pipeline's output,
generated by `python -m src.dashboard.build_dashboard_json` from the
repo root. No backend, no runtime API calls; everything is fetched
from relative `./data/*.json` paths bundled into the static build.

## Local development

From the repo root, make sure the dashboard JSON exists:

```bash
python -m src.dashboard.build_dashboard_json
```

Then, in `site/`:

```bash
npm install
npm run dev
```

`predev`/`prebuild` (see `package.json`) always sync
`../data/outputs/dashboard/*.json` into `public/data/` first
(`scripts/sync-dashboard-data.mjs`) -- there is never a hand-copied or
stale local JSON file to forget about.

## Build

```bash
npm run build   # syncs data, type-checks, builds to dist/
npm run preview # serve the production build locally
```

`vite.config.ts` sets `base: '/epl-2026-27-predictor/'` for GitHub
Pages; adjust `REPO_NAME` there if the repo is ever renamed.

## Deployment

`.github/workflows/deploy.yml` builds and deploys `dist/` to GitHub
Pages on every push to `main`. It builds from whatever
`data/outputs/dashboard/*.json` is already committed -- it does **not**
re-run the Python prediction pipeline itself. `.github/workflows/weekly_update.yml`
is what regenerates and commits fresh JSON: it runs daily, locks any
real gameweek that has newly and fully concluded, refits, re-predicts
the rest of the season, and rebuilds the dashboard JSON -- a genuine
no-op on days nothing concluded (see
`reports/epl_2026_27_model_report.md` "Automated trigger"). That
commit is what then triggers this deploy workflow. You can also
regenerate and commit the JSON yourself at any time if you want the
live site to reflect a new pipeline run sooner.

## Pages

- **Table** -- expected final table with 5th-95th percentile position bands
- **Races** -- title, top-4, relegation probability charts
- **Fixtures** -- matchweek-by-matchweek predictions with scoreline distributions and model-vs-market detail
- **Model** -- backtest comparison, calibration reliability curve, and the ensemble significance result
